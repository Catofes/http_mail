# v0.1.0

首个 Go 版本：将 Python 2 / Falcon 邮箱管理程序迁移到 Go、Echo v4 和 PostgreSQL。程序编译为静态二进制，运行时无需 Python 或系统 libcrypt。

## 接口兼容

- 保留原有 17 个 API 路径、HTTP 方法、查询参数、JSON 字段、业务错误码和权限规则。
- 保留成功写入的 HTTP 200 / 空正文、空列表的 `result: null`、没有 DKIM 记录时的空正文。
- 管理账户密码继续使用原盐值和 SHA512 截断格式；邮箱密码继续使用 `$6$` SHA512-crypt。
- token 仍保存在内存中，固定 24 小时过期；服务重启后需要重新登录。
- 直接使用现有数据库表，不自动建表或修改数据库结构。保留 `my_networks` / `mynetworks` 两个原表名以及默认 Transport 的实际 LMTP 写入行为。

## 安装与迁移

1. 下载对应架构的 `http_mail-linux-amd64` 或 `http_mail-linux-arm64`，并用 `SHA256SUMS` 核对下载文件。
2. 把 `config.json.example` 复制为 `config.json`，填写原数据库的连接配置；`password_salt` 必须沿用原值，否则已有管理账户无法登录。
3. 停止旧 Python 服务，以新程序接替。默认监听地址仍为 `0.0.0.0:8000`，可通过 `-config` 和 `-listen` 指定配置和监听地址。

Docker 镜像为 `ghcr.io/catofes/http_mail:v0.1.0`，提供 linux/amd64、linux/arm64。运行时将实际配置只读挂载到 `/app/config.json`，并设置容器可达的数据库地址。

## 构建与发布

- Makefile 提供代码检查、PostgreSQL 接口测试、双架构编译、Docker 构建和镜像启动检查。
- GitHub Actions 对 PR / 主分支执行构建验证；`v*` tag 发布双架构 GHCR 镜像及 GitHub Release，预发布不更新 `latest`。
- 发布附件包括两个 Linux 二进制、配置示例、README 和 SHA256 校验和。

## 验证与回退

本地验证覆盖格式、go vet、单元测试与 race、独立 PostgreSQL 全接口与事务回滚、amd64 Docker 构建与启动检查，以及双架构静态二进制和校验和。生产邮箱库及邮件客户端收发尚未验证；发布流程不部署服务。

本次没有数据库结构或密码数据转换。若需回退，停止 Go 服务，恢复原 Python 服务及原 `config.py`；`legacy/` 保留原 Python 源码与说明。切换服务会清空内存会话，客户端需要重新登录。
